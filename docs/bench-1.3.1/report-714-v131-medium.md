# Memu Bench 714 全量评测报告（1.3.1）

## 测试配置

- 插件：`dsh-memu-memory` **1.3.1**
- 整理模型：`dys-router` / `deepseek-v4.1-flash`，思考强度 `medium`
- 作答模型：`dys-router` / `deepseek-v4.1-flash`，思考强度 `high`
- 评测规模：714 题全量（6 个 Persona）
- 并发：8（persona 流并行 3 + 组内题目并发）
- 记忆流程：每个 Persona 一个私有库，按 cutoff 升序增量追加冻结历史；每个 cutoff 整理完成后作答该题
- 作答格式：`brief` 简明备忘录（结论/人物/地点/时间/事情/原话/不确定）
- 判分：`deepseek-v4.1-flash`（关闭思考），单批最多 50 题

## 判分口径

本评测只评**记忆复原**：

- 只核对事实与具体信息（人物、时间、地点、原话、约定、边界内容）是否被正确记住；
- `required` 中本质是「建议怎么做 / 应该追问 / 表达方式」的要点，只要记忆事实复原就算满足；
- `无关旧事` 不作为失败依据；
- 失败只记记忆层面的硬错误：错认 / 错否 / 越界 / 编造日期 / 不当私事披露 / 违反禁止 / 未知当事实。

## 流程要点

1. 每个 Persona 一条种子会话，按 cutoff 升序增量追加冻结历史。
2. 每个 cutoff 先整理新增记忆（`generatePrivate`，`force=true`），再考该 cutoff 的题；考完回滚考试回合误写入的条目。
3. 矛盾条目不替模型裁决：接受为 `active` 且 `coexist`，双方保留，作答模型自行取舍。
4. 所有记忆库跑前全部新建；旧的 102 个库与 103 个会话 scope 已清理。
5. 判分按记忆复原口径核对；额外补充但无证据的日期/细节会记 `未知当事实` 或 `编造日期`。

## 稳定性与修复

- 461 个 checkpoint 全部完成，714 题全部作答。
- 整理失败 7 次（461 次里 1.5%），均在重试路径内，无崩溃。
- 判分第一次在 `required` 长度校验处崩溃；已改为按 rubric 长度归一化（缺的记 false、多的截断）并打日志。
- 判分第二次遇到模型返回未知题号；已改为只告警并忽略，缺失题按轮补判，三轮仍缺失才补一条“未通过”的保守记录。
- 一次判分批出现 JSON 转义错误，自动退避重试成功。
- 判分口径调整：`required` 不再作为失败依据，失败只看记忆硬错误；`无关旧事` 不作为失败依据。
